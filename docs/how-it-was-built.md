# 从 0 到 1 实践复盘：怎么用 DSH 把这个项目做出来

> 一句话：重点不是「AI 生成」，而是「怎么把 AI 用起来」——尤其是一路踩坑、拆解、绕路的解决步骤，比最终成品更值钱。

## 一、我是怎么 harness 的

整个过程跑在 DeepSeek Harness（下称 DSH）的**标准模式**下：文件读写、Shell、网页检索、Skills、计划、目标、子代理、工作流，一整套工具都挂在模型手里。我没有给它写脚本或配置，只是像跟同事说话一样把需求丢过去、在关键节点做判断。

下面按时间线，把「用了 DSH 的什么、为什么这么用、当时发生了什么」拆开讲。

### 1. 起步：标准模式 + 完整工具链
第一个 prompt 就是一段完整需求（公众号视图排版 Skill）。模型没有立刻写代码，而是先列目录、查 Node 版本、试网络通不通。这一步用的就是最基础的「文件 / Shell / 检索」能力——先摸清环境，再动手。

### 2. 发现旧项目：澄清式提问
目录里已经有一个同名项目，但定位冲突（旧的是「内容写作」，新的是「视图排版」）。它没有默认覆盖，而是弹出一个**澄清式提问**，给了三个选项（扩展 / 重建 / 新建），我选了「删除重建」。

> 这一步很关键：遇到「会破坏已有工作」的歧义，好的 agent 会停下来问，而不是自作主张。

### 3. 需求落地：自主任务规划
确认方向后，它把一个大需求拆成 **9 步任务清单**（清理 → 骨架 → 主题 → 解析 → 渲染 → CLI → 文档 → 示例 → 测试），逐项推进。我全程没管它怎么排，只盯结果。

### 4. 写码自测：工具闭环 + 自我修复
它一边写一边跑测试。中途列表解析出了 bug（空行后有序/无序列表被并成一个），它自己定位、修掉、再回归，测试从 26 个涨到 39 个全过。这个「写 → 测 → 失败 → 修 → 再测」的闭环，是它最值钱的地方。

### 5. 连续迭代：多轮追加需求
跑通之后，我连续追加了两轮：加「引用模块」、把风格换成「Anthropic 研究页风」。每一轮它都直接接住、落地，而不是推倒重来。

### 6. 读图：子代理不行，就换 OCR
我想让它读素材里的 8 张截图。先让它自己读——模型没视觉；再派**子代理**读——子代理也没视觉；最后用 **tesseract.js 做 OCR**，把截图文字全部转了出来。这里的关键：遇到能力边界别卡死，换工具链。

### 7. 发布：后台任务 + 无头浏览器 + GitHub API
为了「一键复制到公众号」，它起了**后台任务**跑 npm/OCR，用**无头浏览器**（puppeteer-core）出长截图，用 **GitHub API** 传图床、建仓库、改名。

## 二、问题解决实录：最值钱的部分

### 2.1 「一键复制」是怎么啃下来的（重点）

这是全程最绕的一个问题。要的是「图片也自动插好、复制一下就能发公众号」，不想手动传图。我一路试了四种方案：

1. **方案一：base64 内嵌。** 把图片直接编码进 `<img src="data:image/png;base64,...">`。结果：公众号编辑器**不支持 base64 图片**，粘贴时直接丢弃。
2. **方案二：本地文件路径。** `<img src="01.png">`。结果：本地路径对公众号毫无意义，图片全部裂开。
3. **定位根因。** 连续撞墙之后才想明白：公众号要的是「它自己的服务器能访问到的公网 URL」。于是把问题拆成三个子问题逐个击破：
   - **图怎么读？** 模型没视觉 → 子代理也没视觉 → **OCR 兜底**。
   - **图放哪？** 需要公网图床 → 用现有 GitHub 账号建图床仓库，配 **jsDelivr CDN**（国内可访问、免备案）。9 张图全部返回 200。
   - **怎么「一键复制」？** 生成一个带按钮的 HTML，点一下用 `execCommand('copy')` 把富文本复制进剪贴板，粘贴时公众号自动去拉 jsDelivr 的图。
4. **收尾的小坑。** jsDelivr 首次访问返回 301（还没缓存），就先 curl 预热一遍，全部转 200。

最后产出 `article-copy.html`：双击打开 → 点「📋 一键复制」→ 到公众号 Ctrl+V，图片自动加载。

### 2.2 其它踩过的坑（按出现顺序）

- **列表解析 bug**：空行后不同列表类型被错误合并 → 加类型判断修复。
- **字体名破坏 HTML**：`"Segoe UI"` 里的双引号把 `style="..."` 属性截断 → 统一对样式值做 HTML 转义。
- **sharp 压缩反而变大**：默认 PNG 编码不如原图 → 换成调色板量化（palette），体积砍半。
- **OCR 缓存污染仓库**：tesseract 把 traineddata 下到项目根目录 → 加进 `.gitignore`。
- **本地文件夹重命名被锁**：DSH 会话的工作目录就是这个文件夹，Windows 不允许重命名进程当前目录 → 得关掉会话再手动改名。

### 2.3 踩坑的通用套路

回头看，每个问题都是同一套解法：

1. 先确认「到底卡在哪」——是模型能力、外部环境、还是自己逻辑。
2. 把大问题拆成可分别验证的小问题。
3. 一个方案不行就换，别在同一个方向死磕。
4. 每步都留一个可验证的结果（测试通过、HTTP 状态码、文件是否生成）。

## 三、几条可复用的实践

1. **先让它干活，别急着聊架构**：一个真实任务会逼出框架的全部关键机制。
2. **把需求拆到它能接住**：大需求拆成可验证的小步骤，用任务清单跟踪。
3. **关键节点敢拍板**：它停下来问的时候，给出明确取舍（比如「删除旧项目重建」）。
4. **让它边做边测**：别一次性梭哈，每个阶段都有测试兜底、能自我修复。
5. **多轮迭代比一次到位靠谱**：先跑通最小版，再一轮轮加需求、换风格。
6. **遇到能力边界就换工具链**：模型没视觉就上 OCR，要截图就上无头浏览器。

## 结论

「是不是 AI 写的」是伪命题；「怎么把 AI 用起来、卡住了怎么一步步拆开解决」才是真功夫。这个仓库本身就是这套方法的产物——上面每一个坑都真实发生过，也都解决了。
