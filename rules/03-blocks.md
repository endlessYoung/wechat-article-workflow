# 规则 03：代码块、引用、列表与分隔线

## 1. 代码块

- 多行代码使用围栏 ``` 包裹，并**标注语言**（` ```python `、` ```js `），便于读者和工具识别。
- 短代码（一行以内）用行内代码 `` ` `` 包裹，不要单独成块。
- 代码块内的内容**原样保留**：不改标点、不加空格、不改逻辑；这是排版规则的唯一"禁区"。
- 代码块前后空一行。
- 若代码很长，考虑在代码前用一句话说明"这段代码做什么"，降低阅读门槛。

引导语示例见 `templates/block-intros.md`。

## 2. 引用（blockquote）

- 引用用于：他人观点、金句、政策原文、案例数据。
- **必须注明出处**（作者/书名/来源/时间），否则读者无法判断引用价值。
- 样式二选一（全篇统一）：
  - 纯文本式（推荐公众号纯文本输出）：用「」包裹，如
    > 「人们容易高估决定性的时刻，却容易低估每天微小的改进。」—— 詹姆斯·克利尔《掌控习惯》
  - 编辑器样式：粘贴后在后台套用"引用"样式。
- 引用前用一句话引出，如"作家 XX 曾说："。
- 不要引用一大段（> 3 行）还不解释；引用后最好接一句你的解读。

## 3. 列表

- **同级符号统一**：无序列表全用 `-`（引擎默认把 `*`/`+` 归一为 `-`）。
- **步骤/顺序用有序列表**（`1. 2. 3.`），让读者知道先后。
- 列表项要短：一项一行，≤ 30 字为佳；长项拆成"短标题 + 说明"两行。
- 列表前用引导语（"主要有三点："、"落地路径如下："），读者知道接下来会看到什么。
- 一屏内不要连续堆 3 个以上列表；列表之间穿插正文。

## 4. 分隔线

- **全文统一一种分隔线**：`---`（通用）或 `✦ ✦ ✦` / `◆ ◆ ◆`（装饰感强，适合公众号）。
- 一篇文章 1-3 处，用于明显的话题切换；不要每段都用。
- 分隔线不是装饰工具，是"篇章边界"信号：用在章节大切换处。
- 引擎默认输出 `---`，可用 `--divider "✦ ✦ ✦"` 切换。

## 5. 常见错误清单

- [ ] 代码块未标注语言 / 围栏未闭合
- [ ] 代码块内被"自动排版"改了内容
- [ ] 引用无出处
- [ ] 无序列表混用 `-`、`*`、`+`
- [ ] 列表项是一整段话（超过两行）
- [ ] 分隔线样式不统一 / 使用超过 3 处
