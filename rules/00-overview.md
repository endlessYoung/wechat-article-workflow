# 规则 00：排版总则

> 适用范围：所有公众号文章的排版。优先级低于"不改变原文事实"这一底线。

## 1. 读者与平台特征

- 手机端阅读：屏幕小、碎片时间、边走路边刷。
- 扫读为主：读者先看标题、加粗句、列表，再决定要不要细读。
- 完读率 = 信息密度 × 节奏感 × 可读性。

## 2. 排版五原则

1. **清晰**：一个段落只讲一件事；一句话一个信息点。
2. **节奏**：长短句交替；段落短小；每 3-5 段有一个"小高潮"（要点、金句、转折）。
3. **留白**：段间空行、标题前后空行、列表项之间不粘连；留白是排版的一部分，不是浪费。
4. **一致**：同级标题风格统一、列表符号统一、分隔线全文只有一种、引号用法统一。
5. **克制**：加粗每屏 ≤ 2-3 处；不滥用感叹号、emoji、颜色；标题不夸张。

## 3. 规则索引与优先级

| 优先级 | 规则 | 内容 |
| --- | --- | --- |
| P0 | `01-typography.md` | 标点、空格、数字、强调——读者第一眼就感知到的部分 |
| P0 | `02-structure.md` | 标题层级、段落节奏、留白 |
| P1 | `03-blocks.md` | 代码块、引用、列表、分隔线 |
| P1 | `04-tone.md` | 引导文案、过渡句、结尾 |
| P0 | 底线 | 不改事实、不破坏代码/链接、不新增原文没有的内容（除非用户要求） |

## 4. 引擎与 Agent 的分工

- **引擎（src/）负责机械规则**：标点全角化、中英文空格、标题标记规范、分隔线统一、超长段落拆分等。这些是确定性、可测试的。
- **Agent 负责创意规则**：开头钩子、章节过渡句、结尾 CTA、语气把控。这些需要理解语境，引擎不做。
- 协作方式：Agent 可以先跑引擎拿机械处理结果，再手工补创意文案；也可以纯手工按本规则集排版。

## 5. 验证方式

- 输出前过一遍 `SKILL.md` 第 6 节自检清单。
- 需要机器校验时：`node bin/wechat-format.js <input> --check`（有警告时退出码非 0）。
